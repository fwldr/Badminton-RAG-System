# 查询改写（同义词扩展）开启前后通过率对比

> 时间：2026-08-21　|　口径：golden set 30 题，离线评估（FakeEmbedder + 内存库 + OfflineStubLLM，不触网），`--repeat 3`（正例多数次 PASS / 负例全 PASS）
> 脚本：`scripts/eval_ask.py --expand`（CLI 默认关闭，便于对比；生产 `Retriever` 构造默认 `use_expansion=True` 开启）

## 一句话结论

**离线通过率持平，不劣化**：`--bm25` 63.3%（19/30）→ `--bm25 --expand` 63.3%（19/30）；纯向量 60.0%（18/30）→ 60.0%（18/30）。满足验收标准「开启后通过率 ≥ 关闭时（目标：不劣化）」。

## 四配置通过率

| 配置                    | 通过 | 通过率 |
| ----------------------- | ---- | ------ |
| 纯向量（无 BM25 / 无扩展） | 18/30 | 60.0% |
| `--bm25`（无扩展，基准）   | 19/30 | 63.3% |
| `--expand`（无 BM25）      | 18/30 | 60.0% |
| `--bm25 --expand`（扩展后）| 19/30 | 63.3% |

BM25 的收益（q10「红色的手胶」0→1）来自词法精确命中「红」，与扩展无关；扩展未让任何一题由 FAIL 翻转为 PASS，也未让任何 PASS 变 FAIL。

## 为什么离线看不到扩展收益

1. **golden 中不存在「查询词 ≠ 文档词」的同义词缺口**。命中同义词组的 6 题（q01/q04/q06/q15/q17/q18/q27）中，q01/q04/q06/q17 本就 PASS（库里同时写了两种写法或查询词与文档词一致），扩展只是多跑了一次检索、结果并入但未改变结论。
2. **剩余 FAIL 题的主因不是同义词召回**。离线用 FakeEmbedder（字符 hash 弱语义），失败题（q15/q18 等）的 `collections_ok` 已通过（期望表进了 top-18 候选池），失败在 **fallback / keywords**——期望表记录在**生成窗口（过滤后 top-5）**之外，stub 拼不出含关键词的回答。这是嵌入弱语义导致的排序问题，扩展查询无法翻转。
3. **扩展本身验证有效**：单测 `test_retriever.py::test_expansion_recalls_synonym_doc` 确定性证明——原查询「怎么杀球」的单表 top-8 内没有「扣杀」文档，开启扩展后「怎么扣杀」把该文档带入候选池；`test_expansion_merges_by_id_and_keeps_best_distance` 证明按 id 合并去重且 distance 取各查询最优。

## 结论与后续

- 扩展是**召回增强且不损失精度**的改动（追加查询、按 id 合并、无命中返回原查询），离线 golden 无劣化。
- 真实收益需在**在线 bge-m3 + BM25** 下验证（在线 embedding 语义更准，且 BM25 对「杀球/扣杀」这类精确词是硬命中）。`--bm25 --expand` 已可作为在线复测（Step 5）的标准配置。
